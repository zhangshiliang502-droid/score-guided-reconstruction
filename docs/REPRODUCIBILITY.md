# Reproducibility

This guide covers training on new data, re-evaluating the supplied results,
and running the released experiment configurations. Commands assume the
repository root as the working directory.

## Supported claims

| Claim | Status | Additional material |
|---|---|---|
| Fit a new point cloud | Supported | User-supplied `N x 3` or `N x D` array |
| Inspect retained 3D results | Supported | Git LFS objects |
| Re-evaluate all 27 retained 3D results | Supported after `git lfs pull` | 54 bundled SHA-256-identified inputs; `--asset-root .` |
| Run the six analytic high-dimensional configurations | Data generation, training, reconstruction and evaluation scripts included | CUDA server |
| Retrain the exact selected 3D checkpoints | Not supported by the bundled material | Original dense score caches or score-support samples |

Training on a new 3D cloud constructs a Gaussian-KNN score from that cloud.
Retraining a selected paper model additionally requires its original dense
score support, as explained below.

## Validation profiles

`tools/validate_release.py` uses only the Python standard library.

```bash
# Source code and configurations.
python tools/validate_release.py --profile source

# Source plus retained checkpoints and meshes.
python tools/validate_release.py --profile results

# Retained results plus all bundled 3D evaluation inputs.
python tools/validate_release.py \
  --profile lowdim-evaluation \
  --asset-root .

# Generated analytic high-dimensional arrays.
python tools/validate_release.py --profile highdim-data

# Complete low- and high-dimensional paper inputs.
python tools/validate_release.py \
  --profile paper \
  --asset-root .
```

The low-dimensional profile checks file size and SHA-256 against
`example/lowdim/evaluation_assets.json`.

## Analytic high-dimensional benchmark

Each configuration defines data generation, training, reconstruction and
evaluation. Preview one experiment or run the complete benchmark:

```bash
python tools/reproduce_highdim.py \
  --examples example_6d \
  --dry-run

python tools/reproduce_highdim.py \
  --examples all \
  --output-root runs/paper_highdim \
  --device cuda
```

The driver writes generated arrays beside their configurations and run
artifacts under the selected output root. Completed stages are reused. Use
`--stages` to select any subset of `generate`, `train`, `reconstruct` and
`evaluate`.

The repository includes the six result summaries. Trained high-dimensional
checkpoints and reconstructed point sets are generated by the commands above
and are not included in the download.
The retained summaries match the manuscript's Table 4. This numerical agreement
does not independently verify the runs that produced them: that would require
the corresponding trained checkpoints and point sets, or a new training run.

## Retained three-dimensional benchmark

Retrieve and validate the selected outputs:

```bash
git lfs pull
python tools/validate_release.py --profile results
```

If a checksummed result archive is supplied separately, install it with:

```bash
python tools/install_paper_results.py \
  --archive /path/to/score-guided-reconstruction-results.zip
```

The 54 exact evaluation inputs are included under `datasets/` and are fetched
by the same `git lfs pull`. Use the repository root as the asset root, as
described in [`DATA_LAYOUT.md`](DATA_LAYOUT.md), then run:

```bash
python tools/validate_release.py \
  --profile lowdim-evaluation \
  --asset-root .

python 03_evaluation/evaluate_lowdim_benchmark.py \
  --asset-root .
```

To regenerate the retained SGR--DWG comparison from validated extractions:

```bash
python 03_evaluation/evaluate_lowdim_comparison.py \
  --asset-root . \
  --sgr-extraction-root /path/to/sgr_bbox10_runs \
  --dwg-extraction-root /path/to/dwg_bbox10_runs \
  --output-dir runs/lowdim_unified_bbox10
```

DWG is an external method and is not implemented in this repository.

To extract all 27 SGR checkpoints again, use:

```bash
python 01_lowdim_sgr/code/reconstruct_lowdim_benchmark.py \
  --asset-root . \
  --output-root runs/sgr_benchmark \
  --gpus 0
```

The default uses one GPU. A comma-separated `--gpus` list runs independent
datasets concurrently on the specified devices.

## Evaluation protocol

The 3D benchmark approximates point-to-surface RMSE by nearest distances between
one million independent area-weighted reference samples and one million
reconstruction samples. It reports squared bidirectional Chamfer distance from
the same samples and complete-mesh ghost components. The ghost threshold
is three times the median eighth-nearest-neighbor spacing of the full input
cloud.

The high-dimensional benchmark uses 100,000 input projections and 250,000
retained reconstruction points. A reconstructed point is classified as a
ghost when its reference distance is strictly greater than three times the
median eighth-nearest-neighbor spacing of the configured reference sample.

All distances use the saved mean/max-radius training normalization. Evaluation
fails when a required projection does not converge or when checkpoint metadata
does not match the selected configuration.

## Exact 3D retraining boundary

The selected 3D checkpoints were trained with dense external score support.
Those caches are not part of this repository or the 54-file evaluation
manifest. Their retained metadata records cache version 2. The generic trainer
accepts version-4 input-cloud caches with explicit normalization and sampling
checks, using:

```bash
python 01_lowdim_sgr/code/main.py \
  --point-cloud /path/to/points.csv \
  --score-cache-pt /path/to/input_cloud_v4_cache.pt \
  --output-dir runs/my_dataset \
  --iterations 100000 \
  --lambda-global 1 \
  --seed 20260724 \
  --device cuda
```

This command trains using a previously constructed compatible score cache.
Retraining a selected paper checkpoint requires additional material: an original
version-2 dense cache cannot be passed directly to the version-4 interface.

The supplied meshes and evaluation inputs support retained-result
re-evaluation. Exact selected-model retraining requires the additional dense
score support and a trainer using its matching cache contract.

The sampling name `clamped_gaussian` means `r = max(2.5*sigma + sigma*xi, 0)`.
Retained checkpoints preserve the older label `gaussian_abs` for provenance.
Version-4 readers accept that label only together with the required
`local_radius_negative_policy = clamp_zero` and the other sampling checks.

The manuscript-to-code correspondence and the scope of the numerical audit
are recorded in [`PAPER_ALIGNMENT.md`](PAPER_ALIGNMENT.md).

## Run records

For each formal run, retain the generated data metadata, stage logs,
`main_state.json`, `main_output.json`, checkpoints, reconstruction metadata and
evaluation outputs. Also record the Linux distribution, Python and package
versions, GPU model, NVIDIA driver and CUDA runtime. Fixed seeds reduce, but do
not eliminate, numerical variation across environments.
